
1. Перестань разбрасывать данные по памяти (Полюби Векторы)Каждый раз, когда процессор лезет в оперативку, он ждет около 200 тактов (это вечность). Если данные лежат в памяти друг за другом (линейно), процессор за один раз копирует целый кусок в свой сверхбыстрый кэш (L1).Медленно: Использовать структуры данных, которые прыгают по адресам памяти (например, Node в связных списках или бинарных деревьях, или куча мелких Box, Rc).Blazing Fast: Использовать Vec или SmallVec. Намного быстрее отсортировать и перебрать линейный массив (Vec), чем прыгать по ссылкам в "умной" структуре.2. Используй правильный Layout (Выравнивание данных)Процессор читает память «кэш-линиями» по 64 байта. Сжимай свои структуры данных так, чтобы они занимали как можно меньше места и не пересекали границы этих линий.rust// Плохо: занимает много места из-за выравнивания (Padding)
struct Bad {
    flag: bool,   // 1 байт + 7 байт пустых
    num: u64,     // 8 байт
    flag2: bool,  // 1 байт + 7 байт пустых
} // Итого: 24 байта

// Blazing Fast: сортируй поля от больших к меньшим
struct Good {
    num: u64,     // 8 байт
    flag: bool,   // 1 байт
    flag2: bool,  // 1 байт + 6 байт пустых в конце
} // Итого: 16 байт! В кэш влезет больше таких структур.
Используйте код с осторожностью.3. Избегай Branch Misprediction (Промахи ветвления)В процессоре есть «предсказатель ветвлений». Когда ты пишешь if, процессор пытается угадать, выполнится ли условие, и выполняет код заранее. Если он не угадал — всё сбрасывается, теряется 15–20 тактов.Hint: Если ты фильтруешь данные в цикле (например, if x > 10), отсортируй массив перед этим циклом. По отсортированному массиву предсказатель процессора выдаст 100% угадываний (сначала одни false, потом одни true). Скорость вырастет в разы.4. Никаких аллокаций в горячих циклах (Zero-Cost Abstractions)Выделение памяти в куче (Heap) через String::new(), vec![] или Box внутри циклов — это убийца скорости. Это заставляет программу обращаться к аллокатору ОС.Hint: Выделяй память один раз до цикла. Используй clear() вместо создания нового вектора/строки. Переиспользуй буферы.5. Помоги компилятору сделать авто-векторизацию (SIMD)Современные процессоры умеют делать одну операцию над множеством данных одновременно (SIMD — Single Instruction, Multiple Data). Например, сложить 4 или 8 чисел за один такт.Компилятор Rust умеет превращать обычные циклы в SIMD, но ему часто мешают проверки границ (bounds checks).Hint: Вместо ручных индексов for i in 0..arr.len() { ... arr[i] ... } используй итераторы (arr.iter().map(...)). Итераторы гарантируют компилятору, что выхода за границы массива не будет, и он автоматически превратит твой цикл в ультрабыстрые инструкции SIMD.Summary: Чек-лист в Cargo.tomlИногда самый простой способ ускорить код — правильно его скомпилировать. Проверь, чтобы для релизной сборки у тебя стояло это:toml[profile.release]
opt-level = 3       # Максимальная оптимизация кода
lto = true          # Оптимизация на этапе линковки (выкинет мертвый код)
codegen-units = 1   # Даст LLVM оптимизировать код глобально, а не кусками
panic = "abort"     # Убирает тяжелый код раскрутки стека при панике
Используйте код с осторожностью.И запускай всегда через: RUSTFLAGS="-C target-cpu=native" cargo run --release. Флаг target-cpu=native заставит компилятор использовать вообще все инструкции, которые поддерживает конкретно твой процессор (включая самые свежие AVX/SIMD инструкции).Какой из этих пунктов кажется самым неочевидным? Можем подробно разобрать как итераторы Rust обгоняют обычные циклы for или как замерить скорость (бенчмаркать) через criterion, чтобы точно знать, что код стал быстрее.
