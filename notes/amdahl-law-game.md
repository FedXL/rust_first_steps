# Игра с законом Амдала

Закон Амдала показывает, почему ускорение программы ограничено той частью, которую нельзя распараллелить.

## Цель

Понять на практике, почему добавление потоков, ядер или серверов не дает бесконечного ускорения. Эта игра должна связать Rust с темами из компьютерных систем: производительность, параллелизм, узкие места и стоимость последовательного кода.

## Формула

```text
speedup = 1 / ((1 - p) + p / n)
```

Где:

- `p` - доля программы, которую можно распараллелить.
- `n` - количество ядер, потоков или исполнителей.
- `speedup` - итоговое ускорение относительно одного исполнителя.

## Пример

Если 80% программы можно выполнять параллельно, а 20% всегда остаются последовательными:

| Параллельная часть | Исполнители | Максимальное ускорение |
| --- | ---: | ---: |
| 80% | 2 | 1.67x |
| 80% | 4 | 2.50x |
| 80% | 8 | 3.33x |
| 80% | 16 | 4.00x |
| 80% | бесконечно | 5.00x |

Главный вывод: если последовательная часть равна 20%, программа никогда не ускорится больше чем в 5 раз, даже если добавить бесконечно много исполнителей.

## Идея игры

Сделать маленькую консольную игру на Rust:

1. Игрок видит программу с общей длительностью, например `100 секунд`.
2. Игра показывает, какая часть программы параллелится: например `p = 0.80`.
3. Игрок выбирает количество исполнителей: `1`, `2`, `4`, `8`, `16`, `32`.
4. Программа считает ускорение по закону Амдала.
5. Игра показывает новый runtime и объясняет, почему ускорение упирается в последовательную часть.

## Что закрепить в Rust

- чтение ввода из терминала;
- числа с плавающей точкой: `f64`;
- функции;
- форматированный вывод;
- простые циклы;
- проверка пользовательского ввода.

## Черновой сценарий

```text
Program runtime: 100.0s
Parallel part: 80%

Choose workers: 1, 2, 4, 8, 16, 32
> 8

Speedup: 3.33x
New runtime: 30.0s
Sequential bottleneck: 20.0s

Even with infinite workers, best possible speedup is 5.00x.
```

## Мини-задача

Написать `amdahl_game` как отдельный Rust binary:

```text
cargo new amdahl_game
```

Первую версию сделать без потоков. Здесь важна не настоящая параллельность, а понимание предела ускорения.
